In short

Ymir is a young, accurate Sega Saturn emulator (github.com/ymir-emu/Ymir). The plugin installs and updates its stable releases, finds your Saturn BIOS, starts each game with its own backup RAM, gives it the pack's keys - a key for the next disc too - and shows each game's state in Ymir's own compatibility list.

Getting started

  • Install: Tools > Manage > Emulators > Add, choose Nixx-Ymir, Download. Ymir goes to Emulators\Nixx-Ymir, portable: its settings, BIOS, saves and states stay in that folder. The build matches your processor (AVX2, else SSE2; ARM64).
  • BIOS: Ymir needs a Saturn BIOS in roms\ipl. The plugin looks in RetroArch's system folder and the other emulators' bios folders, recognises a BIOS by its content (as Ymir does - the name does not matter) and copies it. mpr-17933.bin runs American and European discs, sega_101.bin Japanese ones.
  • Games: .chd, .cue (with its .bin), .ccd, .mds, .iso, a .m3u for several discs, or a .zip / .7z holding them - platform Sega Saturn.
  • Ymir's update popup never shows: updates come through LaunchBox (stable releases only).

Playing a game

  • A .m3u starts on its first disc; an archive is unpacked once into Emulators\Nixx-Ymir\Unpacked.
  • The game gets its own backup RAM (the Saturn's memory where games save): Saves\Sega Saturn\<game>.bin in Ymir's folder, named after the .m3u or the disc without "(Disc N)" - the discs of a game share it. Ymir's own setting is put back when it quits.
  • Its state in Ymir's compatibility list shows for a few seconds at the top of the screen (on the loading bar in LiteBox).
  • Quit with Esc or LaunchBox's Exit: Ymir closes cleanly.

F4 and F11 are set in Ymir only where it still had its own default (F3 loads, F11 is a debug trace). F6 / F7 / PageDown / PageUp / Esc are the AutoHotkey script of the emulator entry, active in Ymir's window only.

Compatibility list

Ymir's testers keep a list of games and how far each plays: Nothing, Intro, Menus, In-game, Playable, Perfect. The plugin finds each disc in it by Ymir's own disc hash - the exact dump. When only the product code matches it says so (another release may share it). The list is downloaded at install and again when it is a week old; the Nixx window has a button to download it now. Right-click a game > Nixx-Ymir : Options... shows each disc's state and the testers' notes.

Options

  • Nixx window (Tools > Nixx Integration Plugins Configuration..., page Ymir): the screen every game gets, when the compatibility state is shown at launch (always, only when the game may not play, never), the BIOS found, the list.
  • Right-click a game > Nixx-Ymir : Options...: its discs and their state, its own screen, and its own Ymir settings: deinterlacing, transparent meshes, aspect ratio, integer scaling, rotation, rendering (processor or graphics card); SH-2 cache, CPU clock, CD read speed, region, BIOS; what is plugged in ports 1 and 2; sound interpolation, a forced expansion cartridge.
  • Ymir has no per-game settings: a game's own values are written in Ymir's settings for that game only and put back when Ymir closes. Left on As set in Ymir, the value you set in Ymir applies.
  • Changed in Ymir (F10) during a game, a setting the game's window sets becomes that game's own value; the other games keep theirs.
  • A value Ymir has and the list does not offer is kept, shown "(set in Ymir)". A setting a newer Ymir no longer has is said so and not written.
  • Everything else is Ymir's own: F10 in Ymir.

Saves and save states

  • LaunchBox's save management sees each game's backup RAM and its save states (slots 1-10, one folder per disc in savestates), with backups and restore. A state goes back to the disc it was made on; restoring needs Ymir closed.
  • Ymir's own state\bup-int.bin stays for a disc opened by hand in Ymir.
  • The backup cartridge: a game that has one (Saves\Sega Saturn\<game>.bcr, 4 Mbit) gets it plugged in Ymir for its session, and listed in LaunchBox beside its backup RAM. A game without one plays with none, as Ymir does - except the games that need a RAM or ROM cartridge, which Ymir plugs itself.
  • With RetroArch: right-click the game > Nixx-Ymir : Options... > Its save, with RetroArch: import the game's save from RetroArch's Beetle Saturn (its .bkr, and its .bcr cartridge when it holds saves), or export Ymir's to it - the same formats, no conversion. What is replaced is kept, dated, in Saves\Sega Saturn\replaced. The clock and the console's language are not carried (Ymir keeps one for the whole console and follows the PC's clock). Save states cannot be carried: each emulator reads only its own.

Limits and things to know

  • Save states are only guaranteed between stable releases of Ymir (its own rule).
  • A game played in Ymir before the plugin kept its saves in Ymir's single state\bup-int.bin, not in the game's own file.
  • If you rebind Ymir's keys 1-0 or Ctrl+O, F6 / F7 and the next-disc key send the old ones.
  • A game whose window forces an expansion cartridge does not get its backup cartridge plugged.

If something goes wrong

  • The plugin's log: %LOCALAPPDATA%\lb-integrations-plugins\ymir.log (General tab: "Open the logs folder").
  • "Ymir needs a Sega Saturn BIOS": put one in Emulators\Nixx-Ymir\roms\ipl or RetroArch's system folder.
  • "Ymir is already running": close the Ymir already open - two would share one folder of saves.
