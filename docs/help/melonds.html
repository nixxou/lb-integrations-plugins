In short

melonDS is an emulator for the Nintendo DS and the Nintendo DSi. LaunchBox has no standalone DS emulator of its own (only RetroArch), so this plugin adds Nixx-melonDS to LaunchBox's Add Emulator window.

What it does for you:

  • Downloads melonDS and keeps it up to date from LaunchBox.
  • Gives melonDS a playable keyboard layout (melonDS comes with no keys set at all).
  • Finds your BIOS, firmware and DSi NAND files and sets them up in melonDS for you. You only drop the files in a folder.
  • Picks DS or DSi mode for each game on its own.
  • Runs DSiWare (the downloadable DSi games): it installs the game into a DSi console, picks a console of the right region, and keeps each game's save small and separate.
  • Lets LaunchBox see, back up, restore and delete your saves and save states.
  • Lets you give one game its own video and console settings.

Plain DS games need nothing more than the game file. DSiWare needs files from a real DSi, which you must provide yourself (see Getting started).

Getting started

1. Install melonDS

  • In LaunchBox, open Tools > Manage > Emulators, click Add, and choose Nixx-melonDS. Use the download button to install it.
  • melonDS goes into LaunchBox\Emulators\Nixx-melonDS. The emulator entry is linked to the Nintendo DS platform and set as its default.
  • The plugin sets melonDS up during the install: a saves folder and a savestates folder inside the melonDS folder (so no save files end up next to your games), and a keyboard layout.
  • Games start in fullscreen.

2. Import your games

  • Import DS games into the Nintendo DS platform as usual. Accepted files: .nds, .srl, .dsi, .ids, and games inside .zip, .7z, .rar, .tar or .tgz archives.
  • LaunchBox has no DSi platform. If you keep DSiWare in its own platform, the plugin recognises the names Nintendo DSi and Nintendo DSiWare (any spacing or case). Add that platform to the emulator in its Edit Emulator window. DSiWare can also stay in Nintendo DS: the plugin reads each game file to know what it is.

3. BIOS, firmware and NAND (only if you need them)

All these files go in LaunchBox\Emulators\RetroArch\system. This is RetroArch's folder, on purpose: if you ever set up a DS core in RetroArch, the files are probably already there. The plugin creates the folder if it is missing and puts a short note in it (WHICH-FILES-GO-HERE.txt).

  • A NAND is a copy of a DSi console's internal memory, about 240 MB. You can name it anything. The plugin opens each file of that size and reads which region it comes from (Japan, USA, Europe, Australia, China or Korea). You can put several, one per region you own.

None of these files come with the plugin. They must be dumped from your own console.

Playing a game

A DS game

Click Play. The plugin sets melonDS to DS mode (or DSi mode for a DSi-enhanced cartridge, when the DSi files and a NAND are set up), points it at your BIOS files if you have them, and the game starts straight away. To quit, press Esc (the plugin turns it into melonDS's own quit key, Ctrl+Q).

A DSiWare game: the first time with a new NAND

A DSi has to be set up once (owner name, language, birthday, colour). The plugin does this on a copy of your NAND, never on your file. So the first time you launch a DSiWare game with a NAND that has never been used:

  1. A window says there is no console for this NAND yet. Click Set one up now.
  2. Your NAND is copied into melonDS's dsi folder and melonDS opens on that copy.
  3. A small window over melonDS tells you what to click: File > Boot firmware in melonDS. That starts the DSi menu. (melonDS cannot be told to do this from outside, so this one click is yours.)
  4. Go through the DSi setup, then quit melonDS.
  5. A window asks if the setup worked. Yes, keep it keeps this console. No, throw it away deletes the copy; you will be asked again next time.
  6. The game you launched does not start this time. Launch it again.

This happens once per NAND. Every DSiWare game of that region then uses the same console. Closing the first window cancels the launch: there is no "play without a console", because the setup would then be stored inside each game's save instead.

A DSiWare game: every time after that

  • The plugin picks a NAND whose region matches the game. It reads this from the game file first, and uses the name of the game file (like (Japan)) only to narrow things down.
  • It builds a fresh working console, installs the game in it, puts your save back, and melonDS starts on the DSi menu. Click the game there to play.
  • Why the menu and not straight into the game: tests showed that starting a DSiWare game directly loses its save.
  • The game's information file that the DSi needs (a ".tmd") is found for you: next to your game file if you have one (yourgame.nds.tmd), otherwise from a list inside the plugin, otherwise from Nintendo's update server (only the game's id is sent).
  • A DSiWare game inside an archive works: it is unpacked to a temporary file, installed, and the temporary file is deleted.
  • Relaunching the same game reuses the working console when nothing changed, so it is quick.

When you quit

  • For DSiWare, the plugin notices melonDS has closed and takes what changed (your save) out of the working console.
  • If a game had its own settings (see Options), melonDS's normal settings are put back.
  • If LaunchBox or the PC stopped in the middle of a game, this is fixed at the next launch, or a few seconds after LaunchBox starts.

Windows you may see

  • Files missing: a DSiWare game needs a file you don't have. The window names the files and the folder where they go, and can open it.
  • Waiting for melonDS: you launch a game while melonDS is still closing. The plugin waits up to three minutes. After ten seconds a window shows, with a button to stop waiting (the launch is then cancelled and nothing is lost).
  • This save's console is missing: see Saves.
  • Only one game at a time: a second launch while a melonDS game is on is refused (silently in the first few seconds, so a double click does nothing bad). A launch is also refused, with a message, while melonDS is already open on its own.

Options

Per game: right-click > Nixx-melonDS : Options...

Right-click one DS game, or a selection, and choose Nixx-melonDS : Options.... This entry is shown by the pack's small menu plugin, Nixx-Menus, and only in LaunchBox (not Big Box). The window has these tabs:

  • Session (DSiWare only): where the working console is kept while you play. RAM disk (the default when one is available) is faster and writes nothing to your disk while you play. Disk survives a crash of the PC in the middle of a game. If no RAM disk is available, that choice is greyed out and the window says why.
  • Video: this game's own video settings, the same as melonDS's Video settings window (3D renderer, OpenGL display, VSync and VSync interval, separate thread, internal resolution, improved polygon splitting, high resolution coordinates). Each setting can stay on "Default", which means melonDS's own value.
  • Firmware: this game's own console settings, the same as melonDS's Firmware settings window (user name, language, birthday, favourite colour, message, MAC address). Tick "Overwrite melonDS's firmware settings" to use them.
  • Advanced: shows the settings above as text. Tick Edit by hand to type any melonDS setting yourself instead; the Video and Firmware tabs are then not used. Preview result... shows what melonDS will read for this game. Settings the plugin needs for itself (console type, BIOS, NAND, save folders) are left out.

These settings apply only while that game runs. When melonDS quits, its normal settings come back. If the selected games have different options, a list at the top lets you choose which group to start from; OK applies what you see to all selected games, after asking.

A change you make inside melonDS's own menus while a game with its own settings is running is not kept: melonDS's normal settings are put back when it quits.

For melonDS itself: Tools > Nixx Integration Plugins Configuration...

This window has one tab per plugin of the pack. The melonDS tab holds melonDS's own firmware settings (name, language, birthday, colour, message, MAC address), used by every game that has none of its own. It applies to the melonDS this pack installed (Emulators\Nixx-melonDS). The Open melonDS.toml... button opens melonDS's settings file in Notepad for everything else. Changes are refused while melonDS is running, because melonDS rewrites that file when it quits.

The General tab has a button to open the logs folder, and links to the plugin guides.

Saves and save states

LaunchBox's save management (the game's Saves page, backups, restore, delete) sees three kinds of melonDS save:

  • Cartridge save: the game's own save, a .sav named like the game file. On an install made by this plugin it is in Emulators\Nixx-melonDS\saves; on a melonDS you set up yourself, wherever melonDS keeps it (by default next to the game).
  • Save states: melonDS's 8 slots.
  • DSiWare save: one .dsisave file per game. It holds everything the game changed in the console (the game's save plus the console settings around it), which is usually a few dozen kilobytes instead of a 240 MB console. Backups of it are named after the game, like The Game (USA).dsisave.

Save state keys

These are melonDS's own keys and cannot be changed:

  • Shift+F1 to Shift+F8: save to slot 1 to 8. F1 to F8: load slot 1 to 8. F12: undo the last load.
  • The Save State and Load State buttons of LaunchBox's and Big Box's pause screen use slot 1. Exit sends melonDS's quit key.
  • The plugin only fills these pause-screen scripts when they are empty, so your own scripts are kept.
  • Save states are not available for DSiWare.

DSiWare saves, in more detail

  • Restore puts the save back; the next launch rebuilds the console around it.
  • Delete means "this game was never played": the next launch starts it fresh. Not possible while melonDS is running.
  • If the save was changed by something else (a sync, a restore from another PC, a file you copied), the plugin notices, and the new save wins over the old session.
  • Each DSiWare save remembers which console it was made on, and how to rebuild that console from your NAND file. So if you lose melonDS's dsi folder or move to a new PC, putting the same NAND file back in the BIOS folder brings your saves back.
  • If that NAND file is gone too, a window names it (name, size, fingerprint). You can stop and go find it, or Start a new game on another console of the same region. Your old save is then set aside, not deleted, and comes back the day that NAND file is back.

Limits and things to know

  • You must provide the DSi files. A DSi NAND cannot be created; it must be dumped from a real DSi. The DSi firmware is required for DSiWare even though melonDS may look like it doesn't need it.
  • Region lock. A DSi only runs DSiWare of its own region. Without a NAND of the right region, the game cannot start, and a window says which region is needed.
  • A NAND belongs to one console. A save can only be rebuilt from the very same NAND file, not from another console's dump, even of the same region.
  • One click per DSiWare launch: the game is started from the DSi menu.
  • Disk space: each NAND you set up becomes a console of about 240 MB in melonDS's dsi folder, plus one working console of about 240 MB. This does not grow with the number of games.
  • RAM disk: it needs the free ImDisk driver installed by you, the RAM disk turned on in the pack's installer (NixxIntegrations.exe), and about 300 MB of free memory. If the PC crashes in the middle of a game played on the RAM disk, that session is lost. Choose Disk in the game's Options to avoid this. Without a RAM disk, games simply run from the disk.
  • Per-game settings are written into melonDS's single settings file for the time of the game, then put back. If you open melonDS on its own right after a session that did not end properly, the plugin puts your settings back first.
  • Do not change melonDS's settings while it is running through the plugin's windows: melonDS rewrites its file when it quits.
  • A DSiWare game may be refused by the DSi menu in a rare case: when no real .tmd was found anywhere (no file next to the game, not in the plugin's list, and Nintendo's server unreachable). The plugin then makes one from the game file, and the log says so.
  • The plugin only changes paths it set itself. A melonDS you configured by hand keeps its save folders and BIOS paths.
  • The per-game options are not shown in Big Box.

If something goes wrong

  • The plugin's log: %LOCALAPPDATA%\lb-integrations-plugins\melonds.log (General tab: "Open the logs folder").
  • For more detail in the log, create an empty file named trace in that same folder, then restart LaunchBox.
  • A DSiWare game does not start: check that the three DSi files and a NAND of the game's region are in LaunchBox\Emulators\RetroArch\system. The log names what is missing.
  • The DSi menu shows no game: the log says whether the game could be installed. If the plugin's NAND helper could not be used, the log asks for one manual step: in melonDS, open Manage DSi titles and import the game.
  • The game was not started after the console setup: this is normal. Launch it again.
  • Nothing happens on a second launch: a melonDS game is still on, or melonDS is still closing. Wait a few seconds and try again.
  • Wrong console used: if you have two NANDs of the same region, the one that already has a console set up wins; the log says which one was taken.
