In short

no$gba is a small, free emulator for the Game Boy Advance and the Nintendo DS. With this plugin it can also run DSiWare (the downloadable games of the Nintendo DSi), provided you have your own DSi files (see Limits).

The plugin installs and updates no$gba from LaunchBox, and lets LaunchBox see, back up and restore your saves. Most importantly, it fixes one hidden setting: out of the box, no$gba writes its saves in a compressed format that only no$gba can read. The plugin switches it to the plain .sav format, so the same save works in RetroArch, melonDS, DeSmuME, save editors, RomM or Argosy.

In LaunchBox the emulator is called Nixx-nogba (without the dollar sign).

Getting started

Installing

  • In LaunchBox, open Tools > Manage > Emulators, click Add, pick Nixx-nogba and click Download.
  • The plugin downloads no$gba from its author's site (a single zip of about 210 KB) and unpacks it into LaunchBox\Emulators\Nixx-nogba.
  • It creates the emulator entry with three platforms: Nintendo Game Boy Advance, Nintendo DS and Nintendo DSiware.
  • no$gba has no version number. The "version" you see is the date of the file on the author's server, for example 2025-04-14.

Updating

  • When the author publishes a new zip, LaunchBox offers the update like for any other emulator.
  • An update unpacks over the old files. Your settings, saves and DSi files in that folder are kept.
  • If you installed no$gba yourself (not through the plugin), the plugin still works with it but never offers to update or replace it.

BIOS files (optional for GBA and DS)

  • no$gba runs Game Boy Advance and DS games without any BIOS. BIOS files only add accuracy and the Nintendo boot logo.
  • no$gba only looks for them in its own folder, under fixed names. So put your files in LaunchBox\Emulators\RetroArch\system (the same folder the melonDS plugin and RetroArch use) and the plugin copies them for you, under the right names, before each game.
  • Names it recognises: gba_bios.bin (or biosgba.bin), bios7.bin, bios9.bin, firmware.bin, and for DSi dsi_bios7.bin and dsi_bios9.bin (also bios7i.bin / bios9i.bin).
  • LaunchBox's BIOS list shows them all as optional, and warns when a file there has the wrong size.

Importing games

  • Import your ROMs as usual. Supported files: .gba, .agb, .mb (GBA) and .nds, .srl, .dsi, .ids (DS / DSiWare).
  • Zipped games (.zip, .7z, .rar...) are fine: LaunchBox unpacks them before the game starts (see Limits).

Playing a game

Game Boy Advance and DS games

Click Play. Just before no$gba starts, the plugin:

  • makes sure saves are still written in the plain .sav format (it checks at every launch, because no$gba's own Options > Save Options can quietly undo it);
  • copies any new or changed BIOS file from Emulators\RetroArch\system;
  • puts no$gba back in normal DS mode, starting the cartridge directly, in case a DSiWare game changed that last time;
  • applies the game's own settings if you set any (see Options). They are put back to normal when no$gba quits.

Press Esc to quit no$gba. LaunchBox's and Big Box's Exit button works too.

DSiWare games

The plugin recognises a DSiWare game by reading the file itself, whatever platform it is on. Then it:

  • picks one of your DSi NAND dumps (a copy of a real DSi's memory) that matches the game's region;
  • prepares a working DSi with the game installed in it, and your earlier progress for that game put back;
  • switches no$gba to DSi mode. no$gba shows the DSi menu, and you start the game from there. The game file is also loaded "in the cartridge slot", only because no$gba refuses to start without one: ignore it.

When you quit, the plugin notices no$gba has closed and keeps the progress of that session as the game's save.

The first DSiWare game of a region: setting up the console

A DSi must be set up once (name, language, date, favourite colour), like a new console. The plugin does it by itself the first time you launch a DSiWare game with a given NAND dump: it makes a copy of your dump (your own file is never changed) and, when the dump was never set up, gives it your console's name, language, country, birthday and colour (Your console, in Tools > Nixx Integration Plugins Configuration). The game then starts. A dump from a console that was already set up keeps its owner.

Only when that cannot be done does a window ask "no console for this NAND yet":

  • Set one up now: the plugin makes a copy of your dump (your own file is never changed) and opens no$gba on the DSi menu. Go through the welcome screens, then quit no$gba.
  • A second window asks whether it worked: Yes, keep it or No, throw it away (you will simply be asked again next time).
  • Either way, the game itself does not start this time. Launch it again once the console is ready.
  • This is asked once per dump: every DSiWare game of that region then uses the same console.
If the DSi menu does not come up during this setup, put any small homebrew .nds file at Emulators\Nixx-nogba\dsi\boot.nds. The plugin then uses it to start the machine instead of your game.

Whose name the games show

DS games (and DSi cartridges, which no$gba runs as DS games) show the owner of FIRMWARE.BIN, no$gba's copy of your dsfirmware.bin. The first DS game asks once when your dump belongs to somebody else: your console (Your console in the Nixx window), or the dump's owner. A blank dump simply gets yours, and the no$gba tab of the Nixx window changes it. Your dump itself is never written. DSiWare show each DSi console's own owner: no$gba cannot show another over it.

One game at a time

  • While a no$gba game is starting or running, a second launch from LaunchBox is refused. A double click is ignored silently; after a few seconds you get a message.
  • If no$gba is already open on its own (not launched by LaunchBox), the launch is refused with a message: close it first.

Options

Tools menu

The pack's window, Tools > Nixx Integration Plugins Configuration..., has no no$gba tab: this plugin has no global settings. Its General tab still gives you the logs folder.

Right-click on a game: "Nixx-no$gba : Options..."

Right-click a game (or a selection of games) that no$gba can run and choose Nixx-no$gba : Options.... This entry is shown through the pack's Nixx-Menus helper. It sets this game's own settings, used only while it runs; no$gba's normal settings come back when it quits.

  • Emulation: emulation speed, video output, the GBA screen model (GBA, GBA SP...), the DS 3D renderer.
  • Cartridge: the save chip type (GBA or DS), the light level for GBA games with a solar sensor.
  • Display & sound: screen sizing (force 50% steps, force aspect ratio), screen filter, sound output, sample rate, volume control.
  • Link (GBA games only): number of emulated Game Boys, link cable type, gamepaks in every machine or only the first.
  • Advanced: shows the lines of no$gba's settings file that the game changes. Tick Edit by hand to type your own lines instead (the other tabs are then ignored). Preview result... shows the file as no$gba will read it for that game.

Every setting starts on <Default>, which means "leave it as no$gba has it". Only what you change is kept for the game. Each kind of game (GBA, DS cartridge, DSiWare) is only offered what applies to it. With several games selected, OK applies the window to all of them, after asking.

Three things are never taken from a game's settings, because the plugin sets them itself at every launch: the DS/DSi console mode, how the game boots, and the save format.

Any other no$gba setting (keys, for example) is changed in no$gba itself, as usual.

Saves and save states

Cartridge saves (GBA and DS)

  • no$gba keeps them in Emulators\Nixx-nogba\BATTERY, one .SAV file per game, named after the ROM file. Example: mk.nds saves as BATTERY\mk.SAV.
  • For a zipped game, the name is the file inside the zip, not the zip's name. The plugin knows this, so LaunchBox still finds the save.
  • LaunchBox's save management shows them as Cartridge save (tag SAV): you can back up, restore and delete them.
  • Because they are plain .sav files, you can take them to another emulator, or bring one in.

DSiWare saves

  • A DSiWare game saves inside the DSi's memory, not in BATTERY. The plugin keeps what the game changed as one small file per game, shown in LaunchBox as DSiWare save (tag NAND).
  • Backup, restore and delete work. After a restore, the next launch rebuilds the console around the restored save.
  • A DSiWare save remembers which console it was made on, and it is the same kind of save the melonDS plugin makes, so it can move between the two.

Save states

  • no$gba has one "snapshot" (no numbered slots): F8 writes it, F7 loads it. The plugin fills LaunchBox's pause-screen Save State / Load State with these keys, only if those fields are empty.
  • Snapshots are not listed in LaunchBox's save management. In testing, F8 never left a file on disk, so there was nothing to manage.

Limits and things to know

  • no$gba cannot open archives. Given a zip, it shows a "Cartridge not found" box and waits. So the plugin always switches on Auto-Extract for this emulator, even if you turned it off: LaunchBox then unpacks the game first. This is the only one of your settings the plugin overrides.
  • no$gba has no folder settings. It only reads files from its own folder, under fixed names. That is why the plugin copies your BIOS files there instead of pointing to them.
  • A save's name follows the ROM file name. If you rename a ROM, no$gba looks for a save under the new name. Two versions of a game with different file names have separate saves.
  • Old compressed saves are not converted. The plugin changes the format for saves written from now on; it does not convert saves an earlier no$gba setup already wrote in its own compressed format.
  • Changing some settings in no$gba is undone. The DS/DSi mode, the boot setting and the save format are set by the plugin before every game. If you change them in no$gba, they are put back at the next launch.
  • DSiWare needs your own files, in Emulators\RetroArch\system:
    • the two DSi BIOS files (dsi_bios7.bin and dsi_bios9.bin, 64 KB each);
    • a NAND dump from a DSi of the same region as the game (a Japanese game needs a Japanese dump). Any file name works: the plugin reads the region from inside the dump. If you have several of the same region, the one already set up as a console is used, so your saves stay with it.
    Nothing of this is supplied. If a file is missing, no window tells you: the game starts in normal DS mode and will not run properly, and the reason is written in the log.
  • Setting up a DSi console copies about 240 MB twice, once per dump, ever. It never happens on a normal launch.
  • Internet for DSiWare (rarely). To install a DSiWare game, the plugin needs a small description file for it. It first looks next to the ROM (game.nds.tmd), then in a built-in list of about 1700 titles, and only if neither has it does it ask Nintendo's update server. Only the game's ID is sent. As a last resort it builds one itself; the DSi menu may then refuse to start the game.
  • One DSiWare game at a time. If no$gba is still closing, a DSiWare launch is skipped: launch it again once no$gba has closed.
  • Your own DSi file is kept. If you had set up a DSi by hand in no$gba (a DSi-1.mmc file in its folder), the plugin renames it to DSi-1.mmc.yours instead of overwriting it. It is never deleted.
  • No command-line options. no$gba takes only the game file, so there is nothing to tune on the command line.

If something goes wrong

  • The plugin's log: %LOCALAPPDATA%\lb-integrations-plugins\nogba.log (General tab: "Open the logs folder").
  • A "Cartridge not found" box appears: check that Auto-Extract is on for Nixx-nogba in Edit Emulator. The plugin turns it on, but the log warns you if it finds it off at launch.
  • A save made in no$gba is not readable elsewhere: it was probably written before the plugin was in charge, in no$gba's compressed format. Saves written after the next launch are plain.
  • A DSiWare game runs as a plain DS game, or not at all: look in the log for the reason (missing DSi BIOS, no NAND dump of the game's region...).
  • The DSi menu does not appear during console setup: put a small homebrew .nds at Emulators\Nixx-nogba\dsi\boot.nds and try again. Also check in no$gba's Options > Emulation Setup that nothing was changed by hand.
  • The game's own settings seem stuck after a crash: they are put back automatically at the next launch, when LaunchBox starts, or when you open no$gba without a game.
  • More detail in the log: create an empty file named trace (no extension) in %LOCALAPPDATA%\lb-integrations-plugins and restart LaunchBox.
  • To turn DSiWare handling off: create an empty file named no-nogba-dsi in the same folder and restart LaunchBox. DSiWare games are then started as they are, without any preparation.
  • Report problems at github.com/nixxou/lb-integrations-plugins/issues, with the log attached.
