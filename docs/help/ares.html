In short

ares is the accurate multi-system emulator that grew out of higan: Nintendo (NES to Nintendo 64 and the Game Boys), Sega (Master System to Saturn), NEC (PC Engine and its CD), SNK (Neo Geo and the Pocket), Sony PlayStation, MSX, ZX Spectrum and more.

The plugin installs its latest release, tells it which system each game is, finds your BIOS files and hands them to it, writes the picture you chose before every game, and shows its saves and save states in LaunchBox.

Getting started

  • Tools > Manage > Emulators > Add, pick Nixx-ares and Download: the latest release goes into Emulators\Nixx-ares, with a row for each platform it runs. It becomes the default emulator only of the platforms that had none.
  • The BIOS files you already have (RetroArch's system folder, the other emulators' bios folders) are copied into Emulators\Nixx-ares\Firmware and given to ares.

Which system a game runs as

ares must be told the system; the plugin always tells it, from the first of these that says:

  1. the game's own choice - right-click, Nixx-ares : Options..., "System" (a Sega CD game that needs the 32X, a NES game as Dendy...);
  2. the platform's line in LaunchBox - Edit Emulator > Associated Platforms, the command line --system "Mega CD", as RetroArch's cores;
  3. the plugin's own choice for the platform, and a few extensions that say it: .32x, .sgx, .ndd, .fds.

BIOS

ares asks for no file name: each BIOS is a path in its settings, which the plugin sets. It looks for the usual names (scph5501.bin, bios_CD_U.bin, syscard3.pce, gba_bios.bin, neogeo.zip...), and in Firmware\ for any file whose content is the dump ares knows. The ares page of the Nixx window lists what was found; a game whose BIOS is missing says so instead of starting.

Options

Every game's settings are ares's own: set them in ares's menus. The ares page of Tools > Nixx Integration Plugins Configuration... sets the screen alone (full, borderless, windowed). A game's window - right-click, Nixx-ares : Options... - sets that game's, in tabs, with what goes on ares's command line shown at the bottom:

  • Game - the system ares runs it as, its file, BIOS and saves, its screen;
  • Picture - video driver (OpenGL 3.2, OpenGL 4.6, Direct3D 9.0), scaling (best fit, integer auto or fixed 1x-7x, stretch), aspect (standard, none, anamorphic 16:9), shader (picked as in ares's own Shader menu, its folders as sub-menus), VSync, exclusive full screen;
  • Colour and effects - luminance, saturation, gamma, colour emulation, colour bleed, interframe blending, overscan, pixel accuracy;
  • Sound - driver, volume, mute, dynamic rate;
  • Start and emulation - region order, fast boot, what happens when ares loses the focus, rewind, run-ahead, periodic save, the interpreter for Nintendo 64 and PlayStation;
  • One system's - Nintendo 64 (resolution 1x/2x/4x, supersampling, weave deinterlacing, video interface, Expansion Pak, Controller Pak size), Super Famicom (deep black boost), Game Boy Advance (Game Boy Player), Mega Drive (TMSS). A game's window shows those of its system only.

"As set in ares" says what ares has (read from its settings.bml). Reset to defaults puts every option back on it. Several games selected: the list at the top starts on All selected games - an option they do not agree on shows as Various (purple, with how many games have their own): left so, each keeps its own; changed, it goes to all. The list also offers each group of games with the same options, to start from. OK asks first, and changes only what you changed.

Hotkeys: ares ships none; the plugin binds RetroArch's, when empty: F2 save state, F4 load it, F6/F7 the slot, F full screen, Esc quit, P pause, H reset, F8 screenshot, F9 mute, R rewind (with ares's Rewind option on). A key you bound in ares is kept. ares only hears them while its window has the focus.

They are given on ares's command line (--setting), not written into its settings.bml: ares puts its own values back when it quits, so what one game chose never stays for the next. Every option starts as As set in ares: then nothing is given, and what you set in ares's own menus is used. A --setting you put on the platform's line in LaunchBox (Edit Emulator > Associated Platforms) comes after the plugin's and wins.

Compatibility

A game's window shows its line in ares's own list (ares-emu.net/compatibility): completable, in-game, starts or nothing, the ares version it was tried with and the team's notes. The game is found by its file's name (No-Intro), else by its title. A copy of the list comes with the plugin; it is read again from the site only with Update the list now on the ares page (a few minutes).

Saves and save states

  • Each game's save files, beside the game unless you set a saves folder in ares: a cartridge's .ram, .eeprom, .flash, .rtc (and the Super Famicom's .iram, .bsx, .dram), the Famicom Disk System's .d1a...d2b, the 64DD's .disk, the Neo Geo Pocket's .sav, a tape's recording .wav, the PlayStation's memory card .card and the Nintendo 64's Controller Pak .pak.
  • Each game its own console. ares keeps ONE backup RAM for the whole Mega CD, PC Engine (HuCard and CD) or LaserActive, and one clock for the 64DD, in its Systems\<console>.sys\ folder. The plugin gives each game its own: <game>.bram beside its saves, put in place before ares starts and taken back when it quits. A game with no copy yet starts from the memory as it was before the plugin (kept once as backup.ram.before-nixx), so nothing already saved is lost. The 64DD's clock, <game>.rtc, is backed up and restored with the game's .disk.
  • The Neo Geo Pocket's system RAM (language, clock) and the WonderSwan's owner profile are the console's settings, not a game's save - the games save on their cartridge. One console, set once.
  • A multi-disc game (a .m3u) has one memory card, <m3u name>.card: ares names its card after the disc in the drive, so the plugin puts it under the launched disc's name and brings the last disc's back to the game when ares quits. Save states stay per disc.
  • The Neo Geo's memory card is not kept by ares between sessions.
  • Save states: .bs1 to .bs9. ares ships no key for them: the plugin binds F5 (save) and F7 (load) when they are empty, and LaunchBox's pause screen uses them.

Limits and things to know

  • No RetroAchievements in ares.
  • A disc as an .iso, .bin or .img with no .cue: ares opens discs only through a .cue, so the plugin writes a hidden <game>.cue beside it, once. A cooked (2048-byte) ISO has no CD audio tracks - and on the PlayStation no XA sound or video sectors - so a game may play without its music, or not at all: a .bin/.cue or .chd dump is the safe choice.
  • ares reads .zip, .cue and .chd; a cartridge in a .7z is unpacked by the plugin into Emulators\Nixx-ares\Unpacked, where its saves and states then live; a disc in one is refused. A .m3u starts on its first disc - ares has no playlists.
  • To change discs (PlayStation, Mega CD): leave full screen, then PlayStation (or Mega CD) > Change Disc - the file dialog opens in the game's folder. The PC Engine CD has no disc change in ares.
  • Satellaview and Sufami Turbo games need two cartridges at once: not handled yet.

If something goes wrong

  • The plugin's log: %LOCALAPPDATA%\lb-integrations-plugins\ares.log (General tab: "Open the logs folder").
