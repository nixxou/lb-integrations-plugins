In short

Cxbx-Reloaded is an emulator for the original Xbox. The plugin installs and updates it, and takes care of what it does not do on its own:

  • it plays your disc images (redump .iso, trimmed .xiso, compressed .cso / .cci / .chd), even zipped. Cxbx-Reloaded on its own only opens a game's executable, never an image or an archive;
  • it starts the game full screen in a window, the safe kind of full screen;
  • it puts each game's saves in LaunchBox's save management.

Getting started

Installing Cxbx-Reloaded

In LaunchBox: Tools > Manage > Emulators > Add, pick Nixx-Cxbx and let it download. It goes into Emulators\Nixx-Cxbx, set up as portable: its settings and the Xbox's hard disk (with your saves) stay in that folder, and Cxbx-Reloaded asks you nothing on its first start.

Cxbx-Reloaded only publishes test builds, one per change. The plugin always takes the newest, and LaunchBox's update button tells you when there is a newer one.

Cxbx-Reloaded needs the Microsoft Visual C++ 2015-2022 runtime, 32-bit (x86): vc_redist.x86.exe from Microsoft. Many PCs already have it. If yours does not, the plugin tells you when you launch a game.

LaunchBox has a Cxbx-Reloaded entry of its own. It starts the wrong program and fails, so use Nixx-Cxbx.

Importing games

Use LaunchBox's Import > ROM Files with the platform Microsoft Xbox. Keep your games as they are: .iso, .xiso, .cso, .cci, .chd, .zar, or the .zip / .7z they came in. A .cso or .cci cut in parts (Game.1.cso, Game.2.cso...) is one game: its .1 part. A game already unpacked into a folder can be imported by its default.xbe.

Playing a game

When you click Play, the plugin reads the disc, unpacks the game and starts Cxbx-Reloaded on it. A zipped game is read straight out of the zip: the disc image itself is never written to your drive. A window shows the progress.

  • The first launch of a zipped game takes a while, about a minute for a full redump image. After that it starts at once.
  • If the game fits under a size you choose (4 GB by default), it is unpacked to a RAM disk for the session: nothing is written to your drive, and it is gone when you quit.
  • Otherwise it is unpacked once into a folder on your drive (by default Emulators\Nixx-Cxbx\lbip-games) and reused at the next launches. That folder can have a size limit: when it is full, the games you launched longest ago lose their copy (all of it, never half) and get it back the next time you play them.

Your own files, the zips and the ISOs, are never changed or deleted.

ISO, XISO, CSO, CCI, CHD and ZAR without a copy

With the Arsenal Image Mounter installed, a disc image that is not zipped (ISO, XISO, or a compressed CSO, CCI or CHD, decompressed as the game reads), or a .zar (a compressed archive of the game's files, read as the game asks for them), is not unpacked at all: for the session, the plugin shows it to Windows as a read-only drive holding the game's files, and Cxbx-Reloaded plays from there. Nothing is copied, no RAM disk is used, and the game starts in a few seconds. The drive goes away when you quit. This is on by default; it can be turned off for every game or for one game.

The RAM disk needs a driver (ImDisk or the AIM Toolkit, both in the pack's installer) and the small helper the pack installs, the same one LiteBox uses. Without them, games simply go to the drive.

Full screen

Once the game shows, the plugin presses Cxbx-Reloaded's own Alt+Enter for you: the game fills the screen in a borderless window. Press Alt+Enter again to get a normal window back. Cxbx-Reloaded's other full screen, the "exclusive" one in its Video settings, can freeze the screen on some PCs. If you turn it on anyway, the plugin leaves it alone.

Options

For every game: the Cxbx-Reloaded tab

Tools > Nixx Integration Plugins Configuration..., tab Cxbx-Reloaded: disc images and ZArchives mounted without a copy (Arsenal Image Mounter), the folder games are unpacked into, its size limit, the RAM disk and its threshold, the full screen in a window, and the import: filter out what is not a game, rename games when their name is not in LaunchBox's database (the compatibility list's name, else the game's own), set each game's region after the import. The tab also shows which Cxbx-Reloaded is installed and where it keeps its data. The RAM disk itself is set in the RamDisk & VHDX tab.

For one game: its right-click menu

Right-click a game > Nixx-Cxbx : Options... shows what the game is (title, size, where its saves are), how it runs according to Cxbx-Reloaded's compatibility list (your exact version, then the game's other versions, each with a link to its page), where the next launch will unpack it and why, and lets you:

  • turn the mounting without a copy on or off for this game (grey: as every game);
  • force always a RAM disk or always the disk for this game, when it is unpacked;
  • tick Keep its copy on the disk so the size limit never removes it;
  • delete its copy on the disk.

Cxbx-Reloaded's own settings (graphics, controllers...) are set in Cxbx-Reloaded itself: open cxbx.exe in its folder.

Saves

On an Xbox, each game keeps its saves in a folder of its own on the console's hard disk. The plugin shows that folder to LaunchBox as one file per game: backups are made when you quit a game, and you can restore an older one from LaunchBox. Restoring replaces the game's saves with the backup's.

Close Cxbx-Reloaded before restoring or deleting a save.

Limits and things to know

  • How well a game runs is up to Cxbx-Reloaded, not the plugin, and many games are still far from perfect.
  • Some games restart themselves (a second disc, some menus). Cxbx-Reloaded then starts again in a new window, and LaunchBox may think the game is over. The plugin waits until Cxbx-Reloaded is really gone before it cleans up and backs up the save.
  • One game at a time.
  • What a game stores on the console besides its saves (its cache, some settings) is not part of the backups.
  • On the RAM disk, the unpacked game disappears when the session ends. That is the point: your saves are elsewhere and are kept.

If something goes wrong

  • Nothing starts: check the Visual C++ x86 runtime (the Cxbx-Reloaded tab says if it is missing).
  • "cannot be launched": the message says why (not an Xbox disc, an Xbox 360 game, a damaged image).
  • The screen freezes on start: turn off "Full screen" in Cxbx-Reloaded's Video settings and let the plugin's full screen in a window do the job.
  • The plugin's log: %LOCALAPPDATA%\lb-integrations-plugins\cxbx.log (General tab: "Open the logs folder").
